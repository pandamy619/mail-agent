# Установка и запуск

С 03.09.2026 агент работает на сервере: почта читается по IMAP, а не через
Почту macOS. Разделы «Этап 0–6» ниже описывают историю проекта на маке и
оставлены для справки; актуальная схема — в этом разделе.

## Текущая схема (сервер, IMAP)

Зависимостей нет — только Python 3.11+ и стандартная библиотека.

1. **Ящики** описываются в `config.yaml`, секция `mail.accounts`: имя ящика,
   IMAP-хост и префикс переменных `env`. Папки корзины и черновиков находятся
   автоматически; при необходимости задаются полями `trash` и `drafts`.
2. **Секреты** — в `.env` (скопируйте `.env.example`, затем `chmod 600 .env`):
   для каждого ящика `<env>_USER` (полный адрес) и `<env>_PASS` (пароль
   приложения, не пароль от аккаунта). Где взять пароль приложения — подсказки
   внутри `.env.example`. Ящики без заполненных данных пропускаются
   с предупреждением в логе. Переменные окружения имеют приоритет над `.env`.
   **Папки**: `data/` — правила агента (`rules.md`, создаётся сам) и критерии
   важности (`importance.md`); `state/` — индекс и состояние; `logs/` — логи.
   Всё это в Docker монтируется как volume.
3. **Проверка подключения** (только чтение):

   ```bash
   python3 scripts/test_mail.py            # все ящики
   python3 scripts/test_mail.py Google     # один
   ```

   Показывает число писем, найденные папки корзины и черновиков, поддержку
   MOVE, последние пять писем и текст самого свежего.
4. **Индекс** для мгновенного поиска по всей истории:

   ```bash
   python3 scripts/build_index.py
   ```

   По IMAP это быстро (3 тыс. писем — около 10 секунд). Повторный запуск
   докачивает только новые карточки.
5. **Чат в терминале**: `python3 interfaces/cli.py`. **Telegram-бот**:
   `python3 interfaces/telegram_bot.py`. **Фоновая проверка**:
   `python3 scripts/check_mail.py --loop` (разово — без `--loop`,
   без отправки в Telegram — `--dry-run`).
6. **Тесты** (без сети и модели): `python3 -m unittest discover -s tests -t .`

Что изменилось по сравнению с маком: письма адресуются IMAP UID, поэтому
позиции не «уезжают»; удаление — MOVE в корзину; очистка корзины — EXPUNGE
с пересчётом; черновики (новое письмо и ответ с цитатой) сохраняются в папке
черновиков ящика, отправляете вы из любого клиента.

## Docker (сервер)

Два сервиса из одного образа (`compose.yaml`): `bot` — Telegram-бот,
`checker` — фоновая проверка циклом. Ollama остаётся на хосте (systemd,
`OLLAMA_HOST=0.0.0.0`) и видна контейнерам как `host.docker.internal`.
Время контейнеров — `TZ=Europe/Moscow`: по нему считаются тихие часы,
дайджест и вечерний вопрос про корзину.

```bash
docker compose up -d --build            # собрать и запустить оба сервиса
docker compose logs -f checker          # живой лог (то же видно в Portainer)
docker compose run --rm --no-deps bot python3 scripts/test_mail.py   # проверка ящиков
docker compose run --rm --no-deps bot python3 scripts/build_index.py # индекс
docker compose down                     # остановить
```

Что где лежит: секреты — `.env` (`env_file`, в образ не попадают), состояние
`state/`, память агента `data/`, логи `logs/` — папки проекта, примонтированные
в контейнеры; образ пересобирать нужно только при изменении кода. Контейнеры
работают от uid 1000 (владелец папки проекта), поэтому файлы в volume остаются
вашими. Логи: `logs/agent-bot.log` и `logs/agent-checker.log` (ротация 3×2 МБ)
плюс дубль в stdout для `docker logs`.

Скорость на сервере. Ollama здесь работает на CPU, и обработка промпта
идёт около 11 токенов в секунду для qwen3:14b. Поэтому агент бережёт кэш
промпта: системный промпт с инструментами не меняется между ходами (дата
уходит в сообщение пользователя), модель держится в памяти (`llm.keep_alive`),
окно контекста расширено (`llm.num_ctx`, по умолчанию Ollama даёт 4096 —
промпт агента туда едва помещался). С тёплым кэшем вызов модели занимает
секунды, холодный — минуты; в `logs/` у каждого вызова видно
`prompt=N ток.` — сколько промпта пришлось обработать заново. Фоновые задачи
(классификатор важности, разбор авто-правил) работают на отдельной модели
`proactive.model` (по умолчанию `qwen3:4b`): у Ollama один слот кэша на модель,
и запрос checker'а на модели чата вытеснял бы тёплый промпт бота. Обе модели
живут в памяти одновременно (≈15 ГБ). Для фоновых задач включён режим
размышлений (`proactive.think`): без него `qwen3:4b` отвечает прозой вместо
JSON.

Безопасность (ревью 04.09): бот исполняет команды только от вашего id и только
в личном чате; кнопка «очистить корзины» действует один раз и лишь в день
вопроса; правило добавляется только из вашего сообщения, начинающегося словом
«запомни» (пересказ модели код отклоняет — так текст чужого письма не может
«попросить» агента создать правило «удаляй сам»).

## Этап 0 — фундамент (Ollama + модель + тест)

Всё выполняется в Терминале на маке (Programs → Utilities → Terminal, или Spotlight → «Terminal»).

### Шаг 1. Установить Ollama

Вариант А (проще): скачать приложение с https://ollama.com/download, открыть — в строке меню появится иконка ламы. Ollama будет запускаться сама.

Вариант Б (если пользуетесь Homebrew):

```bash
brew install ollama
brew services start ollama
```

Проверка:

```bash
ollama --version
```

### Шаг 2. Скачать модель

```bash
ollama pull qwen3:14b
```

Это ~9–10 ГБ — займёт время в зависимости от интернета. Понадобится столько же свободного места на диске.

### Шаг 3. Запустить тест

```bash
cd ~/MYPROJECT/mail-agent
python3 scripts/test_llm.py
```

Если macOS предложит установить Command Line Tools для python3 — согласитесь и повторите команду после установки.

### Что должно получиться

```
✅ Ollama запущена (версия …)
✅ Модель qwen3:14b на месте
⏳ Спрашиваю модель…
✅ Модель вызвала sum_numbers(a=379, b=264)
✅ Финальный ответ модели: …643…
🎉 ЭТАП 0 ПРОЙДЕН
```

Пришлите вывод (любой — успешный или с ошибкой) Клоду в чат.

### Необязательно, но полезно

Уточнить точный объём памяти мака — от этого зависит, пробовать ли модель покрупнее:

```bash
sysctl -n hw.memsize | awk '{print $1/1024/1024/1024 " ГБ"}'
```

## Этап 3 — действия с почтой ✅ настроено, ждёт запуска

Запуск тот же: `python3 interfaces/cli.py`. Новые умения:

- «письма от гитхаба в корзину», «перемести письма Ozon в папку Рассылки», «почисти корзину» — агент сначала показывает, что нашёл, и выполняет только после вашего «да»;
- «пометь всё прочитанным» — сразу, без подтверждения (это обратимо);
- «ответь на письмо от Ивана, что я согласен» — откроется окно ответа в Почте с готовым текстом; кнопку «Отправить» нажимаете вы. Агент сам ничего не отправляет.

Очистка корзины нажимает пункт меню Почты «Ящик → Стереть удалённые объекты» через автоматизацию интерфейса — при первом использовании macOS попросит включить для Terminal «Универсальный доступ» (Настройки → Конфиденциальность и безопасность → Универсальный доступ). Результат агент проверяет пересчётом: «было 8, осталось 0».

Как устроена защита: опасный инструмент лишь создаёт заявку (в терминале она подсвечена красным ⚠). Выполнить её может только `confirm_action`, и код требует, чтобы между заявкой и подтверждением было ваше новое сообщение с согласием — модель физически не может подтвердить сама себе. «Удалить» всегда означает «в корзину» (восстановимо); безвозвратна только очистка корзины, и перед ней агент называет, сколько всего писем в корзине. Письма при выполнении сверяются по внутренним id — если ящик успел сдвинуться, агент скажет «нашёл 10 из 12», а не тронет соседние.

Проверочный сценарий этапа: «все письма от гитхаба в корзину и почисти корзину».

## Этап 4 — Telegram-бот ✅ настроено, ждёт запуска

Настройка один раз, ~3 минуты:

1. В Telegram откройте **@BotFather** → команда `/newbot` → придумайте имя и username бота → скопируйте **токен** (строка вида `1234567:AA...`).
2. В папке проекта: `cp .env.example .env` и впишите токен в строку `TELEGRAM_BOT_TOKEN=`.
3. По желанию: в `config.yaml` впишите `default_account: "Google"` — бот не будет уточнять ящик.
4. Запустите бота:

```bash
cd ~/MYPROJECT/mail-agent
python3 interfaces/telegram_bot.py
```

5. Напишите своему боту в Telegram что угодно — он ответит вашим Telegram ID. Впишите его в `.env` в строку `TELEGRAM_USER_ID=` и перезапустите бота. С этого момента бот подчиняется только вам, чужие сообщения игнорирует.

Дальше — как в терминале: «что непрочитанного?», «письма от гитхаба в корзину»… Заявки приходят с кнопками **[Да] [Нет]**. `/new` — новый диалог.

Замечания: бот работает, пока запущен процесс на маке и мак не спит (автозапуск в фоне — этап 5); ответы занимают 10–30 секунд — бот показывает «печатает…».

## Этап 5 — проактивность ✅ настроено, ждёт запуска

Агент сам проверяет почту каждые 15 минут, важное шлёт пушем в Telegram, ночью (23:00–07:00) молчит и копит до утреннего дайджеста в 08:00. Всё меняется в `config.yaml` (секция `proactive`), критерии важности — обычным текстом в `data/importance.md`.

**Основной способ — просто в терминале, без демонов:**

```bash
cd ~/MYPROJECT/mail-agent
python3 scripts/check_mail.py --loop
```

Работает, пока открыт терминал; весь лог на экране; выключить — Ctrl+C. Первая проверка создаст «базовую линию» (запомнит текущие письма) и ничего не пришлёт — пуши пойдут только о письмах, пришедших после.

**Опция на потом — автозапуск через launchd** (когда надоест держать терминал): `bash scripts/schedule_install.sh` ставит то же самое по расписанию, `bash scripts/schedule_uninstall.sh` снимает. При первом фоновом запуске macOS спросит разрешение **для python3** управлять Mail — разрешите (фоновые запуски идут не из Терминала).

Другие режимы того же скрипта:

```bash
python3 scripts/check_mail.py -v              # одна проверка и выход
python3 scripts/check_mail.py --loop --dry-run  # цикл, но пуши печатаются в терминал, не в Telegram
python3 scripts/check_mail.py --reset -v      # стереть состояние, базовая линия заново
```

Проверить работу фонового варианта: `tail -20 logs/agent.log`. Параллельные запуски безопасны — от одновременных проверок защищает lock.

Замечания: пока мак спит, проверки не идут — выполнятся после пробуждения; фоновый режим только читает почту, действий не совершает; поменяли `check_interval_min` — переустановите расписание тем же `schedule_install.sh`.

## Индекс писем — поиск по всей истории

Разово выгружает карточки всех писем (отправитель, тема, дата, статус, id — без текстов) в локальную базу `state/index.db`. После этого поиск отвечает мгновенно и по всей истории, с честным «всего найдено N», а действия работают и со старыми письмами.

```bash
python3 scripts/build_index.py
```

Займёт минуты (зависит от размера ящика), идёт с прогрессом и оценкой времени. Ctrl+C не страшен — прогресс сохраняется, повторный запуск продолжит с места. Пересобрать заново: `--rebuild`, один ящик: `--account Google`.

Дальше индекс поддерживается свежим сам — при каждом скане агента и фоновой проверке. До построения индекса агент работает по-старому (поиск в последних ~100 письмах) и сам подскажет запустить индексацию.

Замечание: чтение и удаление СТАРЫХ писем (глубже последних ~150) требует поиска по живому ящику — на 20 тыс. писем это может занять минуту-другую; агент предупреждает об этом в заявке.

## Этап 6a — правила и память ✅ настроено, ждёт проверки

Агент запоминает постоянные правила — командами в любом интерфейсе:

- «запомни: письма от Тинькофф всегда важны» — правило действует сразу: в чате (CLI и Telegram) и в классификаторе важности фоновых проверок;
- «какие правила?» — нумерованный список;
- «забудь правило 2» — удаление по номеру.

Правила лежат в `data/rules.md` обычным текстом (можно править руками), максимум 50 правил по 200 символов, при конфликте побеждает более позднее. Правила вида «…удаляй сам» пока просто хранятся — действовать начнут на этапе 6b (одной заявкой в день с кнопками).

## Этап 6b — авто-уборка ✅ настроено, ждёт проверки

Правила со словом «сам» работают без вас:

- «запомни: письма от гитлаба старше 3 дней перемещай в корзину сам» — агент проговорит, как понял правило, и с этого дня утром (после дайджеста) сам убирает такие письма в корзину, присылая отчёт «🧹 убрано 118». Это обратимо, поэтому без вопросов.
- Вечером (20:00, настраивается) приходит вопрос: «🗑 В корзине Exchange: 214. Очистить безвозвратно? [Да] [Нет]» — очистка стирает корзину целиком, поэтому только по кнопке; выполняется кодом с отчётом «было/осталось».
- «какие автоматические правила?» — список с интерпретацией и статистикой срабатываний.

Настройки в config.yaml: `cleanup_enabled`, `cleanup_report_time`. Требуется работающая фоновая проверка (`--loop` или launchd) и, для очистки, разрешение «Универсальный доступ» (даётся один раз, см. этап 3).

## Этап 7 — сервер и Docker

См. разделы «Текущая схема (сервер, IMAP)» и «Docker (сервер)» в начале файла.
