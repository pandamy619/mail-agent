# Установка и запуск

Агент работает на домашнем сервере (Ubuntu, Docker): почта читается по IMAP,
модель — локальная Ollama на том же хосте, управление — Telegram-бот.
Зависимостей нет — только Python 3.11+ и стандартная библиотека.

## Настройка

1. **Ящики** описываются в `config.yaml`, секция `mail.accounts`: имя ящика,
   IMAP-хост и префикс переменных `env`. Папки корзины и черновиков находятся
   автоматически; при необходимости задаются полями `trash` и `drafts`.
   Ящик по умолчанию — `mail.default_account` (пусто — агент уточняет в диалоге).
2. **Секреты** — в `.env` (скопируйте `.env.example`, затем `chmod 600 .env`):
   для каждого ящика `<env>_USER` (полный адрес) и `<env>_PASS` (пароль
   приложения, не пароль от аккаунта; где взять — подсказки внутри
   `.env.example`), а также `TELEGRAM_BOT_TOKEN` и `TELEGRAM_USER_ID`. Ящики без
   заполненных данных пропускаются с предупреждением в логе. Переменные
   окружения имеют приоритет над `.env`.
3. **Telegram**: в @BotFather → `/newbot` → токен в `.env`. Запустите бота,
   напишите ему что угодно — он ответит вашим ID; впишите его в
   `TELEGRAM_USER_ID` и перезапустите. С этого момента бот подчиняется только
   вам и только в личном чате.
4. **Папки данных** (в Docker монтируются как volume): `data/` — правила
   агента (`rules.md`, создаётся сам) и критерии важности (`importance.md`,
   обычный текст, правьте руками); `state/` — индекс писем и состояние
   фоновой проверки; `logs/` — логи с ротацией.

## Docker

Два сервиса из одного образа (`compose.yaml`): `bot` — Telegram-бот,
`checker` — фоновая проверка циклом. Ollama остаётся на хосте (systemd,
`OLLAMA_HOST=0.0.0.0`) и видна контейнерам как `host.docker.internal`.
Контейнеры сидят в стандартной сети `bridge`: файрвол хоста пускает к Ollama
только из неё. Время контейнеров — `TZ=Europe/Moscow`: по нему считаются тихие
часы, дайджест и вечерний вопрос про корзину.

```bash
docker compose up -d --build            # собрать и запустить оба сервиса
docker compose logs -f checker          # живой лог (то же видно в Portainer)
docker compose run --rm --no-deps bot python3 scripts/test_mail.py   # проверка ящиков
docker compose run --rm --no-deps bot python3 scripts/build_index.py # индекс
docker compose down                     # остановить
```

Секреты (`env_file`) в образ не попадают; `state/`, `data/`, `logs/` — папки
проекта, примонтированные в контейнеры, поэтому образ пересобирать нужно
только при изменении кода. Контейнеры работают от uid 1000 (владелец папки
проекта), файлы в volume остаются вашими. Логи: `logs/agent-bot.log`
и `logs/agent-checker.log` (ротация 3×2 МБ) плюс дубль в stdout для
`docker logs`. Порт 993 с самого хоста закрыт VPN-маршрутом — проверять
почту нужно из контейнера (команды выше), а не `python3 scripts/…` напрямую.

Без Docker то же самое запускается вручную: `python3 interfaces/cli.py` — чат
в терминале, `python3 interfaces/telegram_bot.py` — бот,
`python3 scripts/check_mail.py --loop` — фоновая проверка (`-v` разово,
`--dry-run` без отправки в Telegram, `--reset` — базовая линия заново).
Тесты без сети и модели: `python3 -m unittest discover -s tests -t .`

## Что умеет агент

**Чат** (Telegram или терминал): «что непрочитанного?», «найди письма от GitLab»,
«о чём последнее письмо от Авиасейлс?», «покажи последние 5 писем в яндексе».
Ящик называйте в запросе, если не задан ящик по умолчанию. `/new` — новый
диалог.

**Действия.** «Письма от гитхаба в корзину», «перемести письма Ozon в папку
Рассылки», «почисти корзину» — агент сначала показывает, что нашёл, и
выполняет только после вашего «да» (кнопка [Да] в Telegram). «Пометь всё
прочитанным» — сразу, это обратимо. «Ответь Ивану, что согласен» — черновик
с цитатой сохраняется в папке черновиков ящика, отправляете вы из любого
клиента; агент сам ничего не отправляет.

Как устроена защита: опасный инструмент лишь создаёт заявку. Выполнить её
может только `confirm_action`, и код требует, чтобы после заявки пришло ваше
новое короткое согласие — модель не может подтвердить сама себе; «стоп»,
«нет» или поправка снимают заявку. «Удалить» всегда означает «в корзину»
(восстановимо); безвозвратна только очистка корзины, и перед ней агент
называет, сколько в ней писем. Письма адресуются IMAP UID, перед действием
сверяются с живым ящиком: чего уже нет — не трогается, отчёт «нашёл 10 из 12».
Инструкции внутри текста писем — не команды: правило добавляется только из
вашего сообщения, начинающегося словом «запомни», пометка прочитанным — только
по явной просьбе, а ответ на письмо с подменённым Reply-To агент отдельно
называет.

**Индекс** (`scripts/build_index.py`) разово выгружает карточки всех писем
(отправитель, тема, дата, статус, UID — без текстов) в `state/index.db`, после
чего поиск по всей истории отвечает мгновенно с честным «всего найдено N».
Дальше индекс обновляется сам при каждом обращении к почте. Ctrl+C не страшен —
повторный запуск докачает остальное; `--rebuild` пересобирает, `--account`
ограничивает ящиком.

**Фоновая проверка** (`checker`) каждые `check_interval_min` минут берёт всё
новое по UID-курсору, классифицирует локальной моделью по `data/importance.md`
и шлёт важное пушем; ночью (`quiet_hours`) молчит и копит до утреннего
дайджеста (`digest_time`). Первая проверка создаёт базовую линию и ничего не
шлёт.

**Правила и память.** «Запомни: письма от Тинькофф всегда важны» — действует
сразу в чате и в классификаторе; «какие правила?», «забудь правило 2».
Правила лежат в `data/rules.md` (до 50 по 200 символов, можно править руками).
Правила со словом «сам» — авто-уборка: «запомни: письма от гитлаба старше
3 дней перемещай в корзину сам» — утром после дайджеста агент сам убирает
такие письма в корзину и присылает отчёт «🧹 убрано 118». Вечером
(`cleanup_report_time`) приходит вопрос «🗑 В корзине: 214. Очистить
безвозвратно? [Да] [Нет]» — очистка только по кнопке, кнопка действует один
раз и лишь в день вопроса. «Какие автоматические правила?» — список
с интерпретацией и статистикой.

## Модели и скорость

Ollama на этом сервере считает в основном на CPU (i7-6700K): обработка промпта
qwen3:14b — около 11 токенов в секунду, а промпт агента с инструментами —
около 2,6 тыс. токенов. Поэтому агент бережёт кэш промпта Ollama:

- системный промпт с инструментами не меняется между ходами (дата уходит
  в сообщение пользователя), при старте бот греет кэш в фоне;
- модель держится в памяти (`llm.keep_alive`), окно контекста расширено
  (`llm.num_ctx`; по умолчанию Ollama даёт 4096, промпт туда едва помещался),
  история диалога режется по бюджету токенов, а не по числу сообщений;
- фоновые задачи (классификатор, разбор авто-правил) идут на отдельной модели
  `proactive.model` (по умолчанию `qwen3:4b`) с включёнными размышлениями
  (`proactive.think`, без них 4b отвечает прозой вместо JSON) и только на CPU
  (`proactive.num_gpu: 0`): у Ollama один слот кэша на модель, и запрос
  checker'а на модели чата вытеснял бы тёплый промпт бота. Обе модели живут
  в памяти одновременно (≈15 ГБ).

Видеокарта (GTX 970, 4 ГБ, драйвер 580) отдана модели чата: 14b кладёт на неё
около трети слоёв — холодный вызов 81 с вместо 300, тёплый 12 с. 4b как
модель чата не годится: рассуждает на тысячу токенов перед каждым вызовом
инструмента (70 с на GPU). В `logs/` у каждого вызова видно размер промпта
`prompt=N ток.` и время — по времени понятно, сработал ли кэш.

## История

Этапы 0–6 (23–26.08.2026) проект прошёл на MacBook Pro: Ollama и qwen3:14b
локально, почта через AppleScript в стандартной Почте macOS, автозапуск через
launchd, очистка корзины кликом по меню через System Events. Решения и уроки
тех этапов (сверка id в момент действия, пересчёт вместо кода возврата, одна
заявка в день на авто-уборку) записаны в `PLAN.md`. 03.09.2026 агент переехал
на сервер: AppleScript заменён IMAP, письма адресуются UID, Docker — этап 7.
