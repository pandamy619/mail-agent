# Почтовый агент — план проекта

Личный агент для работы с почтой в стандартной Почте macOS, работающий на локальной модели (Ollama) на MacBook Pro, с управлением через Telegram и терминал.

Версия плана: 1.0 · 23.08.2026

---

## Правила работы над проектом

1. **Каждый шаг обсуждается заранее. Ничего не выполняется без явного подтверждения Влада.**
2. Каждый этап заканчивается работающей демонстрацией — только после неё переходим к следующему.
3. Все файлы проекта живут в этой папке (`mail-agent`). Секреты (токены) — только в `.env`, который никуда не отправляется.

---

## Зачем этот проект

Три причины. Первая — время: разбор входящих, чистка уведомлений, «найди то письмо» — рутина, которую агент делает за секунды. Вторая — приватность: модель локальная, содержимое переписки не покидает мак и не уходит ни в какое облако. Третья — контроль: это ваш собственный агент, устройство которого вам полностью понятно, без подписок и внешних зависимостей; при желании он позже переезжает на ваш сервер.

## Что агент будет уметь (в готовом виде)

- **Пинговать в Telegram о важных письмах** — по вашим критериям важности — и присылать утренний дайджест входящих.
- **Выполнять команды естественным языком**: «все письма от GitHub в корзину и почисти корзину», «найди письмо от банка за июль», «что нового за сегодня?».
- **Готовить ответы**: агент пишет черновик в Почте, финальную кнопку «отправить» нажимаете вы.
- **Соблюдать постоянные правила**: «уведомления X старше трёх дней удаляй сам» — добавляются командой «запомни: …».
- **Безопасно выполнять массовые операции**: сначала отчёт («нашёл 87 писем»), удаление — только после вашего «да».

## Как это устроено

```
   Telegram ◄────────┐
                     │      ┌──────────────────┐         ┌──────────────┐
   CLI (терминал) ◄──┼─────►│   Ядро агента    │◄───────►│ Ollama (LLM) │
                     │      │ цикл + инструменты│         └──────────────┘
                     │      └────────┬─────────┘
                     │               │ AppleScript (osascript)
                     │               ▼
                     │        Почта (Mail.app)
                     │        все ящики: iCloud, Gmail,
                     │        Яндекс/Mail.ru, Exchange
```

Ядро агента — цикл: ваше сообщение → модель → вызовы инструментов (прочитать, найти, переместить…) → ответ вам. Интерфейсы (CLI, Telegram) — тонкие обёртки над этим ядром. Инструменты почты — обёртки над AppleScript, который официально поддерживается Почтой macOS.

Переносимость заложена с первого дня: адрес модели и все настройки — в `config.yaml`. При будущем переезде на сервер меняются только две вещи — адрес Ollama и реализация почтовых инструментов (AppleScript → IMAP/SMTP), всё остальное не трогается.

## Зафиксированные решения

- **Ящики**: все подключённые — iCloud, Gmail, Яндекс/Mail.ru, корпоративная (Exchange), но каждый запрос всегда адресуется в конкретный ящик (решение от 24.08.2026: единый «Входящие» на 20 тыс. писем Почта резолвит по 7–17 с на обращение — непозволительно медленно). Если ящик не назван, агент уточняет.
- **Железо**: MacBook Pro, 18–36 ГБ RAM.
- **Модель**: `qwen3:14b` — прошла тест этапа 0 (Ollama 0.32.0, tool calling подтверждён). Если памяти 32+ ГБ — позже можно попробовать 30B-класс.
- **Интерфейсы**: CLI для отладки с первых этапов, Telegram-бот — основной интерфейс (этап 4).
- **Язык**: Python 3.11+.
- **Отправка писем**: агент сам письма НЕ отправляет — только черновики. Пересмотрим отдельным решением, если захотите.
- **Канал чтения** (по бенчмаркам 24.08.2026): AppleScript по конкретному ящику узкими батчами — направление списка определяется двумя запросами дат, сканируется одно окно; для непрочитанных сначала только статусы, детали по найденным; поиск в два прохода. Единый «Входящие», трюк с properties и SQLite-индекс отвергнуты/отложены.
- **Логи**: `logs/agent.log` (ротация 3×2 МБ) — все вызовы модели, инструментов и AppleScript с длительностями.
- **Индекс писем** (24.08.2026, по запросу Влада «поиск с самого начала»): локальная SQLite-карта всех «Входящих» (`state/index.db`, только карточки, без текстов). Строится разово `scripts/build_index.py`, дообновляется сама при каждом скане. Поиск — мгновенный по всей истории с total; адресация писем — по стабильным id; перед любым действием — сверка с живой Почтой (принцип пересчёта сохраняется).
- **Автоуборка по правилам (этап 6b)** (решение 24.08.2026): фоновая проверка готовит план уборки по правилам «удаляй сам» и присылает в Telegram ОДНУ заявку с кнопками [Да]/[Нет] в день — принцип «всё изменяющее через подтверждение» сохраняется, но подтверждение одно на пачку.
- **Живой фильтр-исполнитель** (26.08.2026, подтверждён прогоном): массовые операции идут по живому ящику от конца к началу, id берётся из того же чтения, ссылка закрепляется через get (атомарно), долгие скрипты — with timeout 600 с; отчёт «найдено/обработано/осталось». Индекс — только для мгновенного «сколько» и предпросмотра.
- **Сверка id в момент действия** (урок инцидента 25.08.2026 — в корзину уехало чужое письмо): позиции писем валидны только в момент проверки; в живом ящике они сдвигаются приходом новой почты. Каждое удаление/перемещение сверяет id письма непосредственно перед действием; несовпавшие не трогаются и обрабатываются повторной локализацией. Из индекса удаляются только реально обработанные.
- **Очистка корзины** (урок 24.08.2026): в словаре AppleScript команды стирания нет, а delete по корзине Gmail — тихий no-op; настоящая очистка — клик меню «Ящик → Стереть удалённые объекты» через System Events (нужен «Универсальный доступ» для Terminal). Результат ЛЮБОЙ опасной операции проверяется пересчётом, а не кодом возврата.

## Этапы

### Этап 0 — Фундамент ✅ пройден 24.08.2026

Поставить/проверить Ollama, скачать модель-кандидата, прогнать тест tool calling («модель, вызови тестовый инструмент»); создать каркас папок и `config.yaml`.
**Результат:** запускаем тестовый скрипт — модель отвечает и корректно вызывает инструмент.

### Этап 1 — Чтение почты ✅ пройден 24.08.2026

Инструменты только для чтения: непрочитанные, чтение письма целиком, поиск по отправителю/теме/дате. Здесь же macOS запросит разрешение «Автоматизация» для управления Почтой — одноразово.
**Результат:** скрипт показывает последние непрочитанные из всех ящиков.

### Этап 2 — Ядро агента + CLI ✅ пройден 24.08.2026

Цикл агента с инструментами, история диалога, чат в терминале.
**Результат:** в терминале спрашиваем «что у меня непрочитанного от Яндекса?» — получаем осмысленный ответ.

### Этап 3 — Действия с почтой ✅ пройден 24.08.2026

Корзина, перемещение по папкам, пометка прочитанным, черновики ответов. Обязательная двухфазность: массовые и необратимые операции — сначала отчёт, выполнение только после подтверждения.
**Результат:** сценарий «все письма от GitHub в корзину и почисти корзину» работает, с подтверждением.

### Этап 4 — Telegram ✅ пройден 24.08.2026

Бот через BotFather, доступ только с вашего Telegram-id (whitelist), подтверждения кнопками [Да]/[Нет]. Токен — в `.env`.
**Результат:** тот же диалог, что в CLI, — с телефона.

### Этап 5 — Проактивность ✅ собран 24.08.2026 (живая приёмка — в эксплуатации: первый пуш о важном и дайджест подтвердим по факту)

Классификация важности по вашим критериям (сформулируем перед этапом); автозапуск: launchd-расписание и/или правило Почты «запустить AppleScript» для мгновенной реакции; пинг о важном; дайджест по расписанию.
**Результат:** приходит важное письмо → в течение минуты пинг в Telegram.

### Этап 6 — Правила и память · 6a и 6b собраны 26.08.2026 (ждут проверки)

Политика 6b уточнена Владом 26.08: перемещение в корзину по авто-правилам — сам с отчётом (обратимо), подтверждение кнопками — на вечернюю безвозвратную очистку корзины. Кнопка исполняется кодом без участия модели.

Файл `rules.md` с постоянными правилами, команда «запомни: …» для добавления новых, автоприменение правил при каждом разборе почты.

### Этап 7 — Переезд на сервер 🔧 в работе с 03.09.2026

Решения 03.09.2026: агент целиком переезжает на домашний сервер (Ubuntu, Docker); AppleScript удалён, почта — только по IMAP (`imaplib`, зависимостей по-прежнему нет); письмо адресуется IMAP UID; Ollama уже стоит на сервере. Порт 993 из контейнеров пущен в обход VPN (правило в конфиге AmneziaWG). Ящики первой версии: Gmail, iCloud, Яндекс/Mail.ru; Exchange — отдельной веткой, если IMAP открыт (для Exchange Online нужен OAuth). Отправка по-прежнему не делается: черновики кладутся в папку черновиков ящика через IMAP APPEND, SMTP не нужен.

Порядок веток: `feat/imap-mail` (IMAP-бэкенд, проверено на Gmail 03.09, влит в main) → `fix/review-0903` (04.09: исправления ревью — сначала они, чтобы тестировать в контейнере уже исправленный код) → Docker (`compose.yaml`: сервисы `bot` и `checker` из одного образа, Ollama на хосте, `TZ=Europe/Moscow`, наблюдение через Portainer).

Ревью 04.09 (сессия с ревью 03.09 потеряна, переделано заново). Исправлено: инъекция через текст письма → авто-правило «удаляй сам» (код принимает правило только из сообщения пользователя «запомни: …», дословно); бот отвечал владельцу и в группе (теперь только личный чат); кнопка очистки корзин повторялась после рестарта (дата в кнопке, раз в день, смещение апдейтов в `state/`); токен Telegram читался только из файла `.env` (теперь и из окружения); Reply-To, отличный от From, теперь называется в ответе; `.env` и `state/` — права 600/700; окно фоновой проверки 30 → 100 писем. Файлы, которые агент меняет сам (`rules.md`, `importance.md`), переехали в `data/`. Ящики первой версии в Docker: пока только Gmail; iCloud и Яндекс подключаются добавлением строк в `.env`.

Прогон 04.09 на сервере: ответ бота занял 13,5 мин — Ollama на CPU (i7-6700K, 11 ток/с на промпте 14b), кэш префикса ломали дата в системном промпте и выгрузка модели через 5 мин, контекст 4096 не вмещал историю (модель на «покажи письма» вызвала mark_read). Решения (ветка `fix/llm-context`): дата в сообщении пользователя, `keep_alive` 24h, `num_ctx` 16384, промпт и описания инструментов короче на треть, гейт кодом на mark_read. GPU: GTX 970 (4 ГБ) не поддерживается драйвером 610, нужна legacy-ветка 580; 14b в неё не влезет, 4b — целиком.

## Риски и как мы их закрываем

AppleScript медленный на больших ящиках — поэтому все запросы ограничиваем «последними N письмами». Модель 14B может понять сложную команду не так — поэтому всё необратимое проходит через отчёт и подтверждение. Корпоративная почта — стоит убедиться, что автоматизация не нарушает политики компании; до этого агент может работать с ней в режиме «только чтение».
